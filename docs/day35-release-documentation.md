# 35일차: 배포 문서와 데이터 지원 범위

## 배포·검증 명령

- [README 검증 명령](../README.md#검증-명령)에 프런트엔드 검사, Functions API 테스트, Firestore 규칙 및 계정·원장 에뮬레이터 검사를 분리해 기록했다. 프런트엔드와 에뮬레이터는 Node.js 22, Functions는 Node.js 20, Firebase 에뮬레이터는 Java 21을 사용한다.
- [README 배포 구성](../README.md#배포-구성)에 빌드와 프로젝트 ID를 명시하는 배포 명령을 적었다. 실제 배포에는 Firebase 설정, Functions 전용 키, 토스 허용 IP 및 VPC·Cloud NAT 연결이 먼저 필요하다. 37~40일차가 그 준비와 검증 단계다.
- [종목 검색 문서](./stock-search.md)의 Vite 전용 API 설명을 수정했다. 개발은 Vite 미들웨어, 배포는 Hosting 재작성과 `tossApi` Function이 같은 `/api/toss/search` 경로를 처리한다. 종목 목록 캐시는 인스턴스별 메모리이며 배포 환경의 최초 검색 시간은 아직 측정하지 않았다.

## 기존 보유 데이터 정책

이번 출시는 기존 직접 입력형 보유 종목의 **현재 수량과 매수가를 초기 보유용 `LEGACY_IMPORT` 매수 기록으로 이관**한다. 기존 종목 문서는 삭제하지 않으며, 한 번 이관한 기록은 재생성하지 않는다. 실제 이전 매수·매도 내역, 수수료·세금, 실현손익은 보유 스냅샷에 원본이 없어 복원하지 않는다. 새 이관 기록의 날짜와 생성 시각은 이관 시점으로 지정하고 원본 `addedAt`은 별도 메타데이터로 보존한다. 거래 이력 화면에는 `초기 보유 이관`으로 표시한다.

과거 거래 전체를 원장으로 복원하는 기능은 이번 출시 범위에서 제외한다. 사용자가 이전 보유와 동일한 거래를 다시 등록하면 중복 계산될 수 있으므로, 향후 기능은 원본 거래 자료 수집·중복 검사·기존 이관 기록 교체·재계산·되돌리기를 갖춘 별도 작업으로 진행한다. 이미 이전 버전에서 이관된 계정의 기록 날짜는 자동으로 변경하지 않는다. 해당 기록도 `초기 보유 이관`으로 표시해 실제 체결일과 구별한다.

## 프런트엔드 산출물

36일차 변경을 포함한 `npm run build` 결과: JS 1,367.09 kB, gzip 402.82 kB; CSS 132.59 kB, gzip 21.71 kB. JS가 500 kB 경고 기준을 넘는다. 현재 [Content](../src/app/ui/Content/Content.tsx)는 대시보드·시장 탐색·거래 내역·가상 포트폴리오를 모두 정적 import한다.

후속 성능 작업: 페이지별 동적 import와 로딩 상태를 추가하고, 초기 화면 JS와 페이지 이동 시간·회귀 테스트를 비교한다. 현재 크기만으로 기능 결함이 확인된 것은 아니므로 36일차에 출시 허용 여부를 판정한다. 배포 검증 환경의 실제 모바일 로딩 시간은 40일차에 확인한다.
