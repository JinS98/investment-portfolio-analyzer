# 종목 이름 검색

개발 서버를 실행하거나 배포된 앱을 연 뒤 종목명 또는 코드에 `삼성전자`, `애플`, `aapl`, `005930`을 입력합니다.
목록에서 종목을 클릭하거나 방향키와 Enter로 선택한 뒤 조회 버튼을 누릅니다.
종목 코드를 직접 입력하고 조회하는 방식도 유지됩니다.

## 캐시와 성능

- API 서버 인스턴스 메모리에 전체 활성 종목 목록을 24시간 저장합니다. 개발 환경은 Vite 미들웨어, 배포 환경은 `tossApi` Cloud Function입니다. 인스턴스가 재시작되거나 다른 인스턴스가 요청을 받으면 목록을 다시 조회할 수 있습니다.
- 최초 검색에서 7개 시장 목록을 순차 조회합니다. 호출 한도를 위해 요청 사이에 1.1초 간격을 둡니다.
- 여러 검색이 동시에 들어와도 목록을 가져오는 작업은 하나만 실행합니다.
- 만료 후에는 기존 목록을 즉시 사용하며 백그라운드에서 갱신합니다. 실패 시 1분 뒤 재시도합니다.
- 검색용 이름·코드를 미리 정규화하고, 검색어별 결과를 최대 200개 캐시합니다.
- 정확히 일치하는 이름·코드, 접두어 일치, 부분 일치 순으로 최대 20개만 반환합니다.
- 브라우저에는 전체 종목 목록을 보내지 않습니다.
- 브라우저는 정규화한 검색어별 결과를 5분간 최대 100개 보관하고, 동시에 들어온 같은 검색어 요청은 하나로 합칩니다.
- 입력 후 250ms 대기, 이전 요청 취소, 늦게 도착한 결과 무시, 한글 조합 중 검색 보류를 적용합니다.

이전 로컬 API 점검에서 최초 검색은 약 7.8초, 캐시 준비 후 검색은 2~5ms였습니다. 이는 개발 환경에서 측정한 값이며 브라우저의 250ms 입력 대기 시간은 제외합니다. 배포된 Function의 콜드 스타트와 인스턴스별 캐시에 따른 시간은 39일차 검증 환경에서 별도로 확인합니다.

## 확인

`npm run build`

`npm run lint`

`npm test --prefix functions`

브라우저는 두 환경 모두 `/api/toss/search?q=...`를 호출합니다. 개발 환경은 Vite 미들웨어가, 배포 환경은 Firebase Hosting의 재작성 규칙을 거친 `tossApi` Cloud Function이 처리합니다. 캐시는 각 서버 인스턴스의 메모리에 있으므로 전체 인스턴스에 공유되는 영구 캐시로 간주하지 않습니다. 배포 전 Function 키와 토스 허용 IP를 설정하고, 검증 환경에서 실제 검색 응답을 확인합니다.

# 시장 탐색 외부 정보 연동

종목 상세 Drawer는 토스 시세와 일봉을 기본으로 사용합니다. 선택 환경 변수를 설정하면 아래 정보를 추가로 표시합니다.

| 환경 변수                                | 대상      | 표시 정보                 | 캐시 |
| ---------------------------------------- | --------- | ------------------------- | ---- |
| `EODHD_API_TOKEN`                        | 국내·미국 | PER, PBR, ROE, 배당수익률 | 15분 |
| `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` | 국내      | 최근 뉴스 3건             | 15분 |
| `MARKETAUX_API_TOKEN`                    | 미국      | 최근 금융 뉴스 3건        | 15분 |

- 국내 EODHD 심볼은 `{종목코드}.KO`, 미국 심볼은 `{티커}.US`로 변환한다.
- 키가 없거나 해당 데이터가 제공되지 않는 종목은 Drawer에 설정 안내 또는 데이터 없음 상태를 표시한다.
- 로컬 개발 키는 `.env.local`, 배포용 키는 Functions 환경에 설정하고 `VITE_` 접두사를 사용하지 않는다.

## 네이버 뉴스 키 설정 (NAVER API HUB)

1. [네이버 클라우드 플랫폼](https://www.ncloud.com/)에 가입·로그인하고 콘솔에서 NAVER API HUB를 찾습니다.
2. 검색(Search) API 이용을 신청하고 Client ID와 Client Secret을 발급받습니다.
3. 로컬은 `.env.local.example`을 참고해 루트 `.env.local`에 다음 값을 입력합니다. 기존 파일이 있으면 다른 설정은 유지합니다.

```dotenv
NAVER_CLIENT_ID=API_HUB에서_발급받은_Client_ID
NAVER_CLIENT_SECRET=API_HUB에서_발급받은_Client_Secret
```

4. 개발 서버를 재시작(`npm run dev`)하고 시장 탐색에서 국내 종목을 선택합니다. 최신순 뉴스 최대 3건과 원문 링크를 확인합니다.
5. 배포 시에는 `functions/.env.example`을 참고해 `functions/.env` 또는 Functions 환경에 같은 키를 설정하고 다시 배포합니다. 로컬 키만 입력하면 배포 서버에는 반영되지 않습니다.

네이버 뉴스만 설정해도 동작하며 EODHD·Marketaux·토스 키는 이 뉴스 API 호출에 필요하지 않습니다. 종목 상세 전체 화면의 현재가·차트는 기존 시세 연동이 필요합니다.

- 요청 주소와 인증 방식은 [API HUB 뉴스 검색 공식 문서](https://api.ncloud-docs.com/docs/naver-api-hub-search-news)를 사용합니다. 기존 NAVER Developers 검색 API 키는 사용할 수 없습니다.
- 인증 실패 시 API HUB 키와 검색 API 이용 신청 상태를 확인합니다. 키는 서버에서만 사용하며 `VITE_` 접두사를 붙이거나 Git에 커밋하지 않습니다.
- 현재 API HUB는 한시적 무료 제공이므로 신청 시 최신 요금을 확인합니다.
- 뉴스·재무 응답은 서버 인스턴스별로 15분 캐시됩니다. 키 변경 후에는 서버를 재시작하고, 빈 뉴스가 캐시된 경우 캐시 만료 후 다시 확인합니다.

## 국내 연간 재무제표 (OpenDART)

- 루트 `.env.local`에 `DART_API_KEY=발급받은_인증키`를 입력하고 개발 서버를 재시작합니다. 배포 시 Functions 환경에도 같은 키를 별도 설정합니다.
- 시장 탐색에서 국내 종목을 선택하면 연간 매출액·영업이익·당기순이익·자산·부채·자본을 표시합니다. 원화는 억 원 단위이며 표시 통화 설정과 별개로 공시 통화를 사용합니다.
- 전년도부터 최근 3개 사업연도에서 제공되는 최신 연간 보고서를 사용합니다. 각 연도는 연결(CFS)을 우선하고 없으면 별도(OFS)를 조회합니다. 연도·연결/별도 기준과 DART 원문 링크를 함께 표시합니다. 분기·반기 자료는 이번 범위에 포함하지 않습니다.
- 기업코드 목록과 성공한 재무제표는 인스턴스별 하루 캐시, 종목 상세 응답은 15분 캐시합니다. 공시 정정이 캐시에 반영되기까지 지연될 수 있습니다.
- ETF·우선주 등 기업코드가 매칭되지 않는 상품이나 자료가 없는 기업은 안내를 표시합니다. 누락 금액은 0으로 만들지 않고 `-`로 표시합니다.
- 국내 PER·PBR·ROE·배당수익률은 DART 자료로 계산하며 EODHD 키가 필요하지 않습니다. 미국 지표는 기존 EODHD 연동을 사용합니다.

### 국내 핵심 지표 계산 기준

- 재무제표와 같은 연도·연결/별도 기준을 사용합니다. TTM·예상 지표가 아닙니다.
- PER: 화면의 원화 현재가 ÷ 공시된 연간 기본 EPS. EPS는 해당 재무제표 계정에서 우선 조회하고, 없으면 배당 API에서 연결/별도가 일치하는 주당순이익(원)을 사용합니다. EPS가 0 이하이면 `-`입니다.
- PBR (참고): 현재가 ÷ 참고 BPS. 연결은 지배주주지분, 별도는 자본총계를 보통주·우선주 합계 유통주식수(자기주식 제외)로 나눕니다. 종류주별 권리 차이를 반영한 BPS가 아니므로 참고값으로 명시합니다. 비양수 자본·주식수 또는 자료 누락이면 `-`입니다.
- ROE: 연결은 지배주주순이익 ÷ 기초·기말 평균 지배주주지분 × 100, 별도는 순이익 ÷ 평균 자본총계 × 100입니다. 기초·기말 자본이 모두 양수여야 계산하며, 순손실에 따른 음수 ROE는 유지합니다.
- 배당수익률: 같은 연도 보통주 주당 현금배당금(원) ÷ 화면의 현재가 × 100. DART에 공시된 과거 배당수익률을 그대로 가져오지 않습니다. 명시된 배당금 0은 0%, 누락·`-`는 `-`로 표시합니다.
- 원화 원시 주가로 계산하므로 화면을 달러 표시로 바꿔도 지표 값은 바뀌지 않습니다. 유효한 주가가 없으면 PER·PBR·배당수익률은 `-`, ROE는 표시할 수 있습니다.
- 연간 공시 이후 분할·증자·소각은 주당 지표에 자동 보정하지 않습니다. 거래소·증권사 지표와 연도·산식 차이가 있을 수 있습니다. 화면의 계산 기준에서도 안내합니다.
- 배당·주식수 요청이 실패해도 재무제표는 유지하고 부분 지표만 표시합니다. 이때 DART 결과 캐시를 15분으로 줄여 재조회할 수 있도록 합니다.
- [배당 API](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS002&apiId=2019005), [주식 총수 API](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS002&apiId=2020002)를 사용합니다.
- 공식 문서: [기업 고유번호](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019018), [전체 재무제표](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020).

## 미국 연간 재무제표 (SEC EDGAR)

- SEC 공시 조회에는 API 키나 회원가입이 필요하지 않습니다. 자동 조회 식별을 위해 루트 `.env.local`에 `SEC_USER_AGENT="앱이름 본인연락이메일"`을 설정하고 개발 서버를 재시작합니다. 실제 연락 가능한 이메일을 사용하고 `VITE_` 접두사를 붙이지 않습니다. 이 값은 서버의 SEC 요청 헤더로만 전송합니다. 배포 시 Functions 환경에도 별도 설정합니다.
- 티커 → CIK 목록, 기업 공시 목록(Submissions), Company Facts를 서버에서 조회합니다. `.`, `-` 종류주 티커 표기 차이를 정규화합니다.
- 최신 10-K/20-F 및 정정 보고서 중 동일 결산일의 연간 표준 XBRL 자료를 사용합니다. 300~400일의 연간 기간만 사용하며 분기·과거 비교연도·다른 통화·다른 접수번호를 섞지 않습니다. 정정 보고서에 재무자료가 없으면 같은 연도 원 보고서를 확인합니다. 최신 결산일 자료 자체가 없으면 과거 실적을 대신 표시하지 않습니다.
- 국내와 같은 접이식 재무제표 영역에 매출·영업이익·순이익·자산·부채·자본을 표시합니다. 미국 달러는 백만 달러 단위, 다른 통화는 해당 통화의 백만 단위로 표시합니다. 표시 통화 설정과 별개로 공시 통화, 회계연도 종료일, 공시일, SEC 원문 링크를 제공합니다.
- 누락 자료는 `-`로 표시합니다. 부채총계가 없는 경우 동일 보고서·동일 통화의 총자산과 비지배지분을 포함한 총자본이 모두 있을 때만 차감해 구합니다. 개별 기업의 확장 태그만 있는 항목은 추정하지 않습니다.
- 기업 목록·성공한 재무제표는 인스턴스별 하루 캐시, 데이터 없음은 15분 캐시합니다. 같은 종목 동시 조회는 하나로 합치고, SEC 요청은 인스턴스 내 직렬 처리 및 최소 250ms 간격을 적용합니다.
- SEC가 403/429를 반환하면 차단/호출 한도 안내를 표시하고 뉴스는 독립적으로 유지합니다. SEC는 네트워크/IP에 따라 자동 요청을 제한할 수 있어, 연락처 설정만으로 접근이 보장되지는 않습니다. 실패 응답에 연락 이메일이나 외부 응답 원문을 노출하지 않습니다.
- 이번 단계는 재무제표 연결입니다. 해외 PER·PBR·ROE·배당수익률은 기존 EODHD 연동이며, SEC 기반 무료 지표 계산은 다음 단계입니다.
- 공식 문서: [SEC API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces), [자동 조회 지침](https://www.sec.gov/about/developer-resources).

### SEC 403 원인 확인

- 서버 터미널의 `[SEC access denied]` 로그에서 `category`, `reference`, `endpoint`, `retryAt`을 확인합니다. 브라우저 API 응답에는 뉴스와 오류 안내가 함께 전달되므로 HTTP 200일 수 있습니다.
- `rate-limit`: SEC가 요청량 제한 페이지를 반환한 경우입니다. 공유 네트워크/IP의 다른 트래픽도 영향을 줄 수 있어 이 앱의 과다 요청으로 단정하지 않습니다.
- `undeclared-tool`: 요청 식별 정보가 포함되어도 SEC가 해당 트래픽을 자동 도구로 차단한 경우입니다. 운영자의 실제 이름/앱 이름과 연락 가능한 이메일 설정, 서버 네트워크의 허용 상태를 확인합니다.
- 403/429 이후 인스턴스 내 SEC 요청을 10분간 중단합니다. 기존 종목 상세 응답 캐시는 15분이므로 화면 재시도 시 캐시 만료도 고려합니다. 서버 재시작은 캐시를 지우지만 SEC 차단을 해제하지 않습니다.
- 같은 네트워크에서 지속되면 SEC 공식 안내에 따라 공인 IP, 오류 유형, 참조번호, 요청 시각을 첨부해 webmaster@sec.gov에 문의합니다. 자동 문의 발송은 하지 않습니다.
- 원문 HTML·요청 식별 연락처는 로그와 브라우저 응답에 포함하지 않습니다. 참조번호는 서버 진단용으로만 기록합니다.
