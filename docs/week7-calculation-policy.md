### 확인된 제약

- 매수/매도 이력과 실현손익 모델은 없다. `PortfolioHistory`는 일별 자산 스냅샷이며 거래 원장이 아니다.
- `calcPortfolio()`의 전체 합계·비중은 환산 없이 통화를 합산한다. 이를 새 혼합 통화 요약으로 재사용하지 않는다.
- 스냅샷은 원화 정수, 수익률 소수 둘째 자리로 반올림하며 USD가 있고 환율이 없으면 저장을 생략한다.
- 가격 누락 시 매수가를 대입한다. 새 엔진의 평가 결과에서는 실제 시세 확보 여부를 구분해야 한다.
- 기존 수량 입력은 소수를 허용한다. 새 모델에서도 소수 수량을 허용한다.

## 2. 이름과 데이터 경계

- 이력의 표준 이름은 `HoldingHistory`, 입력은 `HoldingHistoryInput`, 거래 구분은 `HoldingHistoryType = 'BUY' | 'SELL'`로 통일한다.
- `PortfolioType = 'REAL' | 'VIRTUAL'` 및 `Portfolio`를 정의한다. MVP는 사용자당 실제 1개, 가상 1개다.
- `HoldingHistory`에 `portfolioId`, `portfolioType`을 포함한다. `PortfolioHistory`와 혼동하지 않는다.
- 보유 식별 기준은 `portfolioId + market + ticker`다. 같은 티커도 다른 포트폴리오와 합치지 않는다.
- 기록의 입력 필드가 원본이고 보유 상태·평단가·실현손익은 재생성 가능한 계산 결과다.
- `realizedPnL`을 저장하더라도 재계산 시 저장값을 신뢰하지 않고 순서대로 다시 계산한다.
- 계산 함수는 Firebase, Zustand, API, 현재 시각 생성에 의존하지 않는다. REAL/VIRTUAL에 따른 계산 분기도 없다.

## 3. 매수·매도 및 비용 정책

이동평균법을 사용하며 가격·비용은 해당 종목 통화로 입력한다.

| 항목                       | 결정                                                              |
| -------------------------- | ----------------------------------------------------------------- |
| 매수 거래금액              | `price × quantity`                                                |
| 보유 원금 `investedAmount` | 현재 남은 수량의 매수 원금. 수수료·세금 제외                      |
| 매수 후 원금               | 기존 보유 원금 + 신규 거래금액                                    |
| 매수 후 평단가             | 새 보유 원금 / 새 수량                                            |
| 일부 매도 후 원금          | 기존 원금 - 기존 평단가 × 매도 수량                               |
| 매도 후 평단가             | 기존 평단가 유지                                                  |
| 매도 실현손익              | `(매도가 - 기존 평단가) × 매도 수량 - 매도 수수료 - 매도 세금`    |
| 전량 매도                  | 보유 항목 제거. 원금·수량 잔여값은 0. 이력과 누적 실현손익은 유지 |
| 재매수                     | 이전 실현손익은 유지하고 새 보유 원금·평단가 계산 시작            |
| 매수 수수료·세금           | 평단가에 포함하지 않고 별도 누적 비용으로 보관                    |

매수 비용까지 반영한 순손익은 다음처럼 구분한다.

```text
unrealizedPnL = 현재 평가금액 - 현재 보유 원금
realizedPnL = 매도별 실현손익 합계 (매도 비용 이미 차감)
totalPnL = realizedPnL + unrealizedPnL
netPnL = totalPnL - 매수 비용 합계
```

`totalPnL`은 계획서의 정의를 유지한다. `netPnL`은 모든 기록 비용을 반영한 별도 값으로 정의한다. `totalFees`, `totalTaxes`는 BUY/SELL 전체 합계이며, 이 전체 비용을 실현손익에서 다시 빼면 매도 비용이 이중 차감되므로 금지한다. 업무 2에서 매수 비용 소계도 표현한다.

## 4. 숫자·통화·가격 정책

- 가격·수량은 유한한 양수, 수수료·세금은 유한한 0 이상 숫자다. 입력에서 생략한 비용만 0으로 정규화한다.
- 곱셈·합산 결과가 유한하지 않으면 계산 실패로 처리한다.
- KR는 KRW, US는 USD로 계산하고 요약은 통화별로 반환한다. 원화와 달러를 더한 단일 합계는 만들지 않는다.
- 이력 계산 엔진은 환율을 사용하지 않는다. 원화 환산 및 환차손익 정책은 이후 평가·히스토리 통합 단계에서 다룬다.
- 내부 평단가·원금·손익은 반올림하지 않고 계산 정밀도를 유지한다. 표시된 평단가를 다음 거래 계산에 재사용하지 않는다.
- `roundMoney(value, currency)`는 표시/외부 출력 경계에서만 적용한다. KRW는 0자리, USD는 2자리, 절반은 절댓값이 커지는 방향으로 반올림한다. 음수 0은 0으로 정규화한다.
- 부동소수점 수량 오차는 `8 × Number.EPSILON × max(1, 보유수량, 매도수량)` 범위에서만 전량 매도로 정규화한다. 이 범위를 넘는 초과 매도는 오류다.
- 현재가 평가 단계는 이력 재계산과 분리한다. 가격이 없으면 새 평가값은 미확정으로 표현하며, 기존 UI의 매수가 대체 동작은 호환 기간에만 유지한다.

## 5. 정렬·검증·재계산 정책

- 대상 Portfolio와 이력을 명시적으로 받아 `portfolioId`로 분리한다. 대상 이력의 `portfolioType`이 Portfolio와 다르면 오류다.
- `date`는 사용자가 기록한 거래일 `YYYY-MM-DD`이며 실제 달력 날짜인지 검증한다. `createdAt`은 기록 생성 시각(epoch milliseconds)이다.
- 정렬은 `date → createdAt → id` 오름차순이다. 마지막 id 비교는 같은 날짜·생성시각에서도 재현 가능한 결과를 위한 결정이다.
- 입력 배열/객체를 변경하지 않는다. 중복 이력 ID는 오류로 처리한다.
- 매도 시점의 보유량으로 검증한다. 미래 매수를 앞당겨 초과 매도를 상쇄하지 않는다.
- 과거 기록 삽입·삭제는 전체 이력을 다시 계산한다. 과거 매수 삭제로 이후 매도가 불가능해지면 변경 전체를 거부한다.
- 오류에는 원인과 해당 이력 ID를 제공한다. 일부 계산 결과를 성공 결과로 반환하지 않는다.
- 8주차 저장 연결에서는 후보 이력 전체를 먼저 검증·재계산하고, 저장 성공 후 상태를 반영한다.

## 6. 기존 데이터 호환 및 이관 정책

### 7주차: 기존 사용처 유지

1. 새 도메인 타입은 `src/types/portfolio.ts`에 작성하고 기존 import 경로를 위해 `src/types/index.ts`에서 재수출한다.
2. 현재 보유 모델은 호환용 `LegacyStockItem`으로 명시적으로 분리한다. 새 필드를 무조건 optional로 추가해 불완전한 새 모델을 허용하지 않는다.
3. 신규 보유 모델은 `averagePrice`를 기준으로 삼는다. 기존 UI가 필요로 하는 `buyPrice`는 어댑터에서 `averagePrice`로부터 만든다. 두 값을 독립 수정·저장하지 않는다.
4. 기존 서비스·스토어는 호환 모델을 유지하며 새 순수 엔진은 독립 검증한다. 기존 `id`, `addedAt`은 호환 계층에서 보존한다.

### 8주차: 저장 구조 이관

대상 경로는 `users/{userId}/portfolios/{portfolioId}` 아래 `holdings`, `holdingHistories`, `snapshots`다.

- 기존 보유는 REAL에만 이관한다. 기본 VIRTUAL은 빈 상태로 만든다.
- 각 기존 행의 수량·매수가로 초기 보유용 BUY 이력을 생성한다. `source: 'LEGACY_IMPORT'`, `legacyStockId`, `importedAt` 메타데이터로 일반 거래와 구분한다.
- 기존 `addedAt`은 실제 거래일 증거가 아니다. 초기 기록 날짜는 이관 기준일이며 UI에서 '초기 보유 이관'으로 표시한다. 원래 `addedAt`은 별도 메타데이터로 보존한다.
- 알 수 없는 과거 비용은 0으로 초기화하되 이관 이전 비용·실현손익은 복원하지 못했다는 데이터 범위를 표시한다.
- 이관 기준일 이전의 수동 이력 추가는 초기 보유와 중복 계산되므로 차단한다. 실제 과거 원장으로 교체하는 별도 복원 기능은 후속 범위다.
- 기존 중복 종목 행은 각 행을 한 번씩 이관한 후 공통 엔진으로 합산한다.
- 이관 ID는 원본 stockId를 기준으로 재실행해도 중복 생성되지 않게 하고, 이관 버전·완료 상태를 기록한다.
- 이관 전후 종목별 수량·원금을 검증한 후 읽기 경로를 전환한다. 실패하면 기존 읽기를 유지한다. 원본을 삭제하거나 두 경로의 데이터를 합쳐 읽지 않는다.
- 기존 일별 `PortfolioHistory`는 그대로 보존한다. 과거 실현손익을 추정해 채우거나 새 계산으로 과거 스냅샷을 덮어쓰지 않는다.
