## 배포 판정 규칙

- D22~D36의 치명적 UI·계산·데이터 이슈와 CI 실패가 없어야 D41 운영 배포로 넘어간다.
- Firebase 및 토스 설정의 실제 완료 여부는 저장소만으로 확인할 수 없다. 콘솔·API에서 확인한 결과를 해당 작업에 기록한다.
- `health` 성공은 Function 구동 확인이다. 토스 허용 IP와 인증은 실제 외부 API 요청 성공으로 판정한다.
- 검증 환경은 운영 Firestore 데이터와 분리한다. 운영 배포 전에는 배포 대상 커밋과 되돌릴 버전을 기록한다.
- 이 일정은 배포까지의 실행 순서다. 37~41일차의 외부 인프라 또는 검증이 막히면 운영 배포 날짜를 밀고 완료 판정을 유지하지 않는다.
